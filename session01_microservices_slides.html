📹 Videocode / Live-Coding #1 Monolith Approach

Ứng Dụng Monolith (Chung 1 JVM & Database)

@Service
@RequiredArgsConstructor
public class MonolithOrderService {
    
    private final UserService userService;       // Direct Dependency trong RAM
    private final ProductService productService; // Direct Dependency trong RAM
    private final OrderRepository orderRepository;

    @Transactional
    public OrderResponse createOrder(Long userId, Long productId, int qty) {
        UserDto user = userService.getUserById(userId);              // Direct RAM method call
        ProductDto product = productService.reduceStock(productId, qty); // Direct RAM method call

        Order order = new Order(userId, productId, product.getPrice() * qty, "CREATED");
        Order saved = orderRepository.save(order);                   // Same DB Transaction
        return new OrderResponse(saved.getId(), user.getName(), product.getName(), order.getTotalPrice());
    }
}
Lesson 1: Hạn chế

⚠️ "Nỗi Đau" Của Kiến Trúc Monolith

1.

Single Point of Failure (Rủi ro sập dây chuyền)

Chỉ cần 1 bug trôi nổi gây OutOfMemory ở tính năng phụ → Sập luôn cả hệ thống bán hàng & thanh toán.

2.

Scale không linh hoạt (Inflexible Scaling)

Muốn tăng năng lực xử lý cho tính năng Tìm kiếm → Bắt buộc phải nhân bản (scale) toàn bộ file app lớn.

3.

Deploy rủi ro & Tốc độ phát triển chậm

Sửa 1 dòng code nhỏ cũng phải Rebuild & Re-deploy lại toàn bộ ứng dụng lớn.

• Single Responsibility: Mỗi service phụ trách 1 nghiệp vụ duy nhất.

• Database-per-Service: Tuyệt đối không chia sẻ CSDL giữa các dịch vụ.

Lesson 2: So sánh

⚖️ So Sánh Monolith vs Microservices

Tiêu chí Monolith Microservices
Giao tiếp inter-service Gọi hàm RAM (Nanosecond) HTTP REST / gRPC (Millisecond)
Quản lý Dữ liệu 1 DB chung (ACID Transaction) Database-per-Service (Eventual Consistency)
Khả năng Scale Scale toàn bộ ứng dụng Scale từng service độc lập
Độ phức tạp ban đầu Thấp (Code nhanh, đơn giản) Cao (Cần DevOps, Tracing, Gateway)
Lesson 2: Lợi ích

🌟 Ưu Điểm Vượt Trội Của Microservices

📈 Fine-Grained Scaling

Scale riêng PaymentService gấp 10 lần vào ngày Flash Sale mà không lãng phí CPU cho các service khác.

🛡️ Isolation & Resilience

Lỗi ở NotificationService không làm gián đoạn trải nghiệm mua hàng của người dùng.

⚡ Autonomy & Speed

Các nhóm Agile nhỏ tự chủ phát triển và deploy service của mình độc lập.

🔀 Polyglot Architecture

Tự do chọn công nghệ tốt nhất (Java Spring Boot cho Order, Python cho AI/Recommend).

Lesson 2: Đánh đổi

💣 Thách Thức & Đánh Đổi (Trade-Offs)

🌐

Network Latency & Reliability (Trễ Mạng)

Mạng có thể bị chập chờn, rớt kết nối hoặc trễ làm ảnh hưởng hiệu năng tổng.

🔄

Distributed Transactions (Mất ACID)

Không thể dùng @Transactional trên 2 DB riêng → Phải triển khai Saga Pattern / Eventual Consistency.

🛠️

DevOps & Operational Complexity

Cần quản lý Service Discovery, API Gateway, Distributed Tracing (Zipkin/Jaeger), Centralized Log.

Thách Thức Trễ Mạng & Blocked Thread

@Service
public class OrderServiceWithRest {
    private final RestTemplate restTemplate = new RestTemplate();

    public boolean checkInventory(Long productId) {
        String url = "http://localhost:8081/products/" + productId;
        try {
            // NGHẼN MẠNG: Gọi qua HTTP chậm hơn hàm RAM 10.000 lần!
            // Nếu Product Service chậm -> Thread ở OrderService bị Block -> Cháy Thread Pool!
            ProductDto product = restTemplate.getForObject(url, ProductDto.class);
            return product != null && product.stock() > 0;
        } catch (Exception e) {
            return false; // Cần Circuit Breaker / Fallback!
        }
    }
}
Lesson 3: Thiết kế theo Domain

🧠 Tư Duy Domain-Driven Design (DDD)

Phương pháp thiết kế phần mềm lấy Nghiệp vụ cốt lõi (Domain) làm trung tâm thay vì xuất phát từ mô hình CSDL (Database-first).

🎯 Bounded Context

Ranh giới nghiệp vụ hữu hạn. Trong ranh giới này, một khái niệm (Model/Entity) có ý nghĩa hoàn toàn rõ ràng và không bị lẫn lộn.

🗣️ Ubiquitous Language

Ngôn ngữ chung thống nhất giữa Lập trình viên và Chuyên gia nghiệp vụ (Domain Expert) để tránh hiểu nhầm yêu cầu.

✂️ Sơ Đồ Quy Trình 4 Bước Tách Monolith

1

Chia Bounded Context

@RestController
@RequestMapping("/products")
public class ProductController {

    @GetMapping("/{id}")
    public ProductResponse getProduct(@PathVariable Long id) {
        // Trả dữ liệu từ Product DB độc lập

    }
}

📹 Videocode / Live-Coding #4 (Phần 2) Port 8082

Xây Dựng Order Microservice Gọi REST API

@RestController
@RequestMapping("/orders")
public class OrderController {

    private final RestTemplate restTemplate = new RestTemplate();

    @PostMapping
    public ResponseEntity<?> createOrder(@RequestParam Long productId, @RequestParam int qty) {
        // 1. Gọi REST sang Product Service ở Port 8081
        String url = "http://localhost:8081/products/" + productId;
        ProductDto product = restTemplate.getForObject(url, ProductDto.class);

        if (product == null || product.stock() < qty) {
            return ResponseEntity.badRequest().body("Hàng không đủ tồn kho!");
        }

        // 2. Tạo đơn hàng thành công
        Map<String, Object> orderResult = Map.of(
            "orderId", UUID.randomUUID().toString(),
            "productName", product.name(),
            "totalPrice", product.price() * qty
        );
        return ResponseEntity.ok(orderResult);
    }
}
